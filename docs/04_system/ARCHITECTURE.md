# Workbench Architecture

Version: workbench-v0.4. Implements PRD/SRS; existing Harness v0.1 remains unchanged.

Same repository: harness/ remains reusable framework core; apps/workbench/ contains the Node HTTP host, Codex process adapter, SQLite store and static browser UI. Runtime data lives in user-local application data outside Git by default. This is an internal framework interface, not a subdirectory business Project Repo.

Use Node built-in HTTP, sqlite, crypto, fs and child_process; no new runtime packages. Minimal package metadata and Node test suite under apps/workbench are explicitly authorized. Start command builds harness before loading its dist API. Codex executable is host-resolved once; client cannot choose an executable, environment or arguments. Existing auth is consumed by Codex, not read by application code.

Process adapter: detached POSIX spawn with argument array, no shell; ignore user config, ephemeral sessions, read-only sandbox, approval never, host allowlisted model selected (Luna default). Pass prompt via stdin. Whitelist runtime environment for PATH/HOME/USER/TMPDIR/SHELL/CODEX_HOME; exclude OPENAI_API_KEY/CODEX_API_KEY and unrelated credentials. Persist/display only recognized safe event summaries and sanitized final text; never raw CLI stderr. Bound bytes, lines, events and timeout. Process group kill and exit confirmation own terminal status.

Integration: parse the versioned canonical application Work Item with a host-owned canonical-target registry at startup; reuse transitionExecutionState for tasks, hashCoreValue for event integrity and immutable snapshots. This does not fabricate ReviewEvidence or GateResult; app-level completion checks are distinct from formal governance Gates. Persistent event chains are application records, not a claim that AuditRecorder has gained a filesystem backend.

SQLite synchronous transactions serialize task and evidence changes. Server binds loopback and checks exact Host/Origin, same-origin CSRF header. Data schema/API details: SDD.md.

Projects service owns bounded GitHub subprocess operations (gh discovered by host, git argument arrays, shell false), SQLite project records and managed workspace roots under application data. CLI credentials consumed by gh only; no auth-file parsing. Git commands disable system/global config, hooks, fsmonitor and file/ext protocols; user repo config cannot select shell commands. Repository creation and selected export writes require explicit proposal/preview confirmation. Per-project operation mutex plus queued/active task guard avoids repo mutation during analysis. Single runtime FIFO queues project messages, preserving legacy direct-task busy rejection. Skill reader only reads bounded nonsymlink instruction files. Existing v0.1 immutable reviews remain historical; v0.2 source requires fresh reviews.
