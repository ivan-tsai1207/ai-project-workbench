# Framework Workbench PRD

Version: workbench-v0.4; authority: PRODUCT_VISION.md.

## Requirements

- WB-001: Select an absolute local Git project path and submit a nonempty analysis task, maximum 8,000 characters. Validate the directory before dispatch; normal users never enter Role/Gate fields.
- WB-002: Run one real Codex CLI task using existing ChatGPT authentication, a host-allowlisted selected model (default gpt-6-luna), explicit read-only sandbox, never-approval and ignored user configuration. No credential copying or paid API fallback. Availability failure is visible and terminal; no fake result or model substitution.
- WB-003: Show running status and safe progress summaries; success requires process exit 0, a turn.completed event, nonempty final Agent text, unchanged Git-visible project fingerprint, and verified application evidence. Process success is not formal Spec/Design/Implementation/Delivery/Release approval.
- WB-004: Cancel an active task by terminating its POSIX process group, escalating to SIGKILL within two seconds and waiting for process exit before terminal status. A cancellation race must never become success. Timeout is 180 seconds, server-owned. At most one active task; additional managed-project messages enter a bounded FIFO queue.
- WB-005: Save task, status, redacted prompt/result/error, model, timestamps and bounded hash-linked event evidence in local SQLite. On restart, formerly active tasks become FAILED_RUNTIME with interrupted reason; no automatic resume. Storage failure stops dispatch/update and is surfaced.
- WB-006: Reuse actual Harness state-transition, parser and hashing APIs and display integration/evidence integrity. Reject illegal lifecycle transitions. Formal gate information is displayed as unreviewed, never forged PASS.
- WB-007: Bind only 127.0.0.1; validate Host and mutating request Origin plus CSRF token; cap request 32KiB and output 512KiB/events4,000. No shell interpolation, arbitrary executable selection or credential output. Render text safely; best-effort token/password redaction before persistence and responses.

## Boundaries and exceptions

One local user can read their chosen Git repository; OS sandbox is Codex's read-only policy, not a newly completed Harness enforcement implementation. Inherited API credentials are excluded. User config and MCP servers/hooks are not loaded via --ignore-user-config; repo instructions remain in effect. Read-only does not guarantee confidentiality against malicious repository instructions or local software; select trusted projects and avoid secrets in task text. Prompt/result redaction is best effort, not DLP certification.

Legacy direct task busy ->409; managed conversations queue; invalid path/input ->400; unauthenticated/unavailable CLI -> visible failure; unexpected protocol, stream limit, timeout, persistence failure, evidence mismatch or project changes -> FAILED_RUNTIME; explicit cancel -> CANCELLED after exit. No automatic retries.

Confirmed: user approved same-repo local MVP; existing CLI ChatGPT login and tiny Luna completion verified. Iteration choice: read-only analysis first. Unknown/deferred: workspace edits, full ExecutionProfile enforcement, formal task reviews, remote access and cloud hosting.

## WB-014 / AC-WB-014 — 一般使用者導向 UX（Human 2026-10-05）

工作台主要服務不熟悉工程工具的專案發起人；信任與單人本機執行邊界保持不變。先定義使用者目標、初次使用與回訪步驟、資訊優先順序、一般用語及失敗恢復，再繪製線框、UI與實作。首頁只呈現「開始新專案」與「接續既有專案」；選擇專案後以對話為主要操作，明確顯示目前狀態與下一步。模型、技能、執行工具、紀錄與證據收於進階設定／操作詳情，保留完整能力但不要求使用者先理解術語。GitHub 說明為「雲端專案資料夾與版本紀錄」，建立私人專案與成果送審仍保留完整命名目標、可見性及明確核准，不隱藏資料公開／上傳影響。可用的模型與工具邊界如 v0.2；不宣稱 Agent 能自動修改程式或原生使用 Claude/ChatGPT。

Acceptance: 未選專案時可看見目的、兩條開始路徑與唯一主要動作；選定後新增表單預設收起，可直接對話並看到下一步。未展開進階區即可完成建草稿與對話；保存步驟有清楚的資料去向與確認。375px/桌面無溢出、鍵盤可操作、載入／失敗／等待有文字說明。證據需區分設計者走查與真實一般人測試；尚無真實一般人測試，不得宣稱已驗證大眾適用性。
